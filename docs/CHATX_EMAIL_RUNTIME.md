# Почта внутри CHATX: исполняемый модуль

## Где пользоваться

В основном приложении откройте **Сообщения → Почта**. Личные и общие ящики находятся в одной рабочей области. Настройки доступны там же и через **Ещё → Почта**. В **Сегодня** показаны только доступные текущему пользователю непрочитанные переписки, черновики и ожидания ответа. Администратор может включить или отключить раздел через настройки функций компании.

Это серверный модуль приложения с PostgreSQL, реальными IMAP/SMTP адаптерами и отдельной постоянной очередью. Установка нового интерфейса без миграций и серверных файлов не включает почту.

## Рабочие функции

| Функция | Поведение |
|---|---|
| Ящики | Личные и общие; проверка подключения, пауза, переподключение, отзыв доступа, роли reader/responder/manager. |
| Провайдеры | Gmail, Яндекс, Mail.ru через разрешённый провайдером пароль приложения; произвольный публичный IMAP/SMTP с проверяемым TLS. Поддержка OAuth Outlook пока не реализована. |
| Синхронизация | Входящие и отправленные папки, порционная загрузка, отдельный курсор новых писем и догрузки истории, UIDVALIDITY, обновления флагов и отметки удаления у провайдера. |
| Чтение | Переписка по темам, поиск текста/адресов, фильтр ящика, собственная отметка прочтения, архивирование, отложенное возвращение, метки и ответственный. |
| История контакта | Адреса из текущей выборки; выбор адреса запускает поиск доступной переписки. Совпадение имени не объединяет разные адреса. |
| Ответ и новое письмо | To/Cc/Bcc, From из подключённого ящика, тема, текст, вложения, версии черновика, ручное разрешение конфликта двух редакторов. |
| Три режима | Внешнее письмо, внутренняя заметка для имеющих доступ к ящику и личная заметка автора. Текст не переносится между режимами автоматически. |
| Шаблоны и подписи | Личные и общие шаблоны, редактирование и удаление; явная вставка подписи/шаблона в черновик. |
| Очередь | Отправка с коротким окном отмены, расписание, отмена до начала передачи, согласование конкретной версии общего черновика. |
| Результат передачи | Принято SMTP, известный отказ, неопределённый результат, частично принятые адресаты; копия в Sent имеет отдельный статус. Прочтение получателем не выдумывается. |
| Работа из письма | Создание настоящей Task, Calendar event, закрытой Page или подтверждённого Decision; привязка уже существующего доступного объекта. Обратные ссылки ведут из карточки объекта к письму. |
| Ожидания | Контролирующий сотрудник, срок, состояние ожидания/ответа/отмены и уведомление при наступлении срока. Это отдельное состояние от непрочитанного письма. |
| Правила | Условия по отправителю, получателю, теме, наличию вложений; метки, ответственный, архив, отложенное возвращение. Предпросмотр выборки и контроль версии правила. |
| Предложение времени | Отзываемая публичная ссылка с выбранными интервалами и сроком действия. Выбор времени создаёт настоящее событие Calendar; гость получает подтверждение и файл ICS. |
| AI | Сводка, варианты ответа, редактирование черновика через реально настроенного провайдера. Результат вставляет человек; отправка остаётся отдельным действием. |
| Уведомления | Общий inbox CHATX: входящее письмо, назначение, срок ожидания, проблема отправки. Работают включение, типы и режим «только назначенное мне». |
| Восстановление черновика | Явно включаемое локальное восстановление текста для текущего аккаунта и компании, срок 24 часа, очистка при выходе, явное подтверждение восстановления. |
| Устройства | Адаптивный интерфейс и русская/английская локализация. На узком экране список, чтение и редактор используют доступную ширину. |

## Подключение настоящего ящика

1. Примените миграции **090–093** штатным `npm run migrate` поверх актуальной схемы приложения. Полный новый запуск использует все миграции 001–093.
2. Установите серверную переменную `EMAIL_ENCRYPTION_KEY`: отдельные 32 случайных байта в base64. Сохраните этот ключ вместе с резервной копией. Потеря ключа требует повторного подключения ящиков; существующие ссылки бронирования зависят от того же ключа.
3. Перезапустите приложение. Фоновый worker включён по умолчанию; `EMAIL_WORKER_ENABLED=false` останавливает автоматическую обработку. `EMAIL_WORKER_POLL_MS` задаёт интервал, по умолчанию 5000 мс.
4. В **Сообщения → Почта → Настройки** выберите провайдера, адрес и пароль приложения. В режиме IMAP/SMTP укажите публичные адреса серверов, порты и тип TLS. Проверка сертификата не отключается.
5. После успешной проверки интерфейс показывает подключённый ящик и разрешает отправку. Синхронизацию можно вызвать вручную; затем worker продолжает её автоматически.
6. Для общего ящика добавьте конкретных сотрудников и выберите их роли. Членство в компании или роль администратора сами по себе не дают доступа к личной почте.

`MAIL_HOST`, `MAIL_USER` и другие `MAIL_*` относятся к служебным приглашениям и сбросу пароля CHATX. Учётные данные подключаемых пользователями ящиков вводятся через интерфейс и шифруются в БД; это другой контур.

**Локальный архив EML** позволяет импортировать файлы писем, вести заметки и связывать их с работой. Он явно обозначается архивом и не выдаётся за проверенный внешний ящик. Временный demo-режим не отправляет внешние письма.

## Запуск сборки

Для существующей Node-инсталляции:

```sh
npm ci --ignore-scripts --no-audit --no-fund
sh scripts/build-pages-editor.sh
npm run migrate
npm start
```

Используйте PostgreSQL 17+, `DATABASE_URL`, постоянное хранилище файлов приложения и `EMAIL_ENCRYPTION_KEY`. Самостоятельные Node-команды получают переменные из окружения процесса; копирование `.env.example` в `.env` автоматически подхватывает Docker Compose, но не обычный `node` без загрузки env.

Для Docker Compose заполните `.env.example`, включая обязательные параметры существующего приложения, сохраните как `.env` и выполните:

```sh
docker compose up -d --build
```

Compose запускает PostgreSQL, отдельный шаг миграций и приложение. Локальные файлы приложения сохраняются на выделенном томе. Письма, MIME-оригиналы, почтовые вложения и черновики сохраняются в PostgreSQL.

Сервис должен работать постоянно и иметь разрешённые исходящие подключения к почтовым серверам. Расписание хранится в БД и переживает перезапуск, но остановленный процесс не может отправить письмо в назначенную секунду: просроченная очередь продолжит работу после запуска.

### Ограничение проверенных бесплатных площадок

На момент проверки 20 октября 2026 официальная документация Render Free запрещает исходящие SMTP-порты 25/465/587 и описывает остановку сервиса после 15 минут без входящего трафика. Бесплатная Render Postgres имеет срок 30 дней. Это не подходит для обещания постоянной рабочей почты с расписанием. Источник: https://render.com/docs/free

Railway разрешает SMTP только на Pro и выше; Free/Trial/Hobby предполагают почтовый HTTPS API. Реализованный здесь IMAP/SMTP адаптер не является таким API. Источник: https://docs.railway.com/networking/outbound-networking

В рамках этой работы платные ресурсы не создавались и действующие чужие проекты не переиспользовались. Для полного публичного включения нужен согласованный постоянно работающий сервер с SMTP-доступом либо отдельная реализация и подключение разрешённого HTTPS/OAuth адаптера.

## Границы данных и действий

- Каждая команда проверяет текущее членство в компании и доступ к ящику. Повтор с тем же ключом идемпотентности также проходит проверку прав.
- Ссылки на Task/Calendar/Page/Decision не расширяют доступ ни к письму, ни к объекту. Создание объекта требует подтверждения его текста и аудитории. Новая Page закрыта по умолчанию.
- Неопределённый SMTP-результат не повторяется автоматически: сервер мог принять письмо до потери соединения. Доступна сверка с Sent. Отзыв доступа во время передачи не уничтожает уже полученный результат SMTP.
- MIME хранится как доказательство; активный HTML не исполняется. Вложения скачиваются отдельным защищённым маршрутом. Если сканер не настроен, статус — `unscanned`, а не «безопасно».
- Общее уведомление не содержит темы, адресов и текста личного письма. При его чтении и подсчёте перепроверяется доступ к источнику. Push и отдельные тихие часы для почтовых уведомлений пока не подключены.
- Публичная ссылка бронирования раскрывает только подтверждённое название и предложенные интервалы. Конфликт не раскрывает названия закрытых событий. Email посетителя — введённый им контакт, а не подтверждённая личность.
- Calendar сериализует изменения затрагиваемых расписаний. Явное сохранение поверх конфликта в собственном редакторе остаётся отдельным человеческим решением. Бронирование по публичной ссылке не может включить такое исключение. Проверка новых повторяющихся серий для этого сценария ограничена первым интервалом и горизонтом предлагаемых слотов в 60 дней; гарантии для бесконечной серии не заявляются.
- Почтовые API и публичные ссылки не кэшируются Service Worker. Восстановление черновика не означает полноценную локальную копию всей истории почты или автономную отправку.

## AI: обработка текста

Внешний режим использует существующую конфигурацию `CHAT_ASSISTANT_PROVIDER` приложения. До вызова требуется согласие на передачу выбранной переписки подключённому провайдеру. Берутся последние 30 сообщений с ограничением объёма; внутренние/личные заметки и вложения не отправляются. Контекст может быть усечён, что отражается в результате. После ответа провайдера повторно проверяются доступ и состояние функции AI.

Для собственного OpenAI-compatible сервера:

```dotenv
EMAIL_AI_PROVIDER=local
EMAIL_AI_BASE_URL=http://127.0.0.1:11434/v1
EMAIL_AI_MODEL=имя_установленной_модели
EMAIL_AI_API_KEY=
```

«Локально» здесь означает инфраструктуру развёртывания CHATX. Это не обещание запуска модели на телефоне или ноутбуке посетителя. Разрешены loopback/private IP, перенаправления запрещены; внешнего fallback нет. В Docker `127.0.0.1` означает сам контейнер: задайте достижимый частный адрес собственного сервера модели. Модель и вычислительный сервер этим модулем не устанавливаются.

## Проверки и сопровождение

Основные исполняемые проверки расположены в `test/email-*.test.js`: доменные правила, PostgreSQL, HTTP, MIME/TLS/STARTTLS, изоляция прав, очередь и неопределённые исходы, общий inbox уведомлений, интеграции с рабочими объектами, календарные гонки, ограниченный пул соединений и настоящий браузер. Они не отправляют письма реальным внешним адресатам.

Полный регрессионный прогон:

```sh
DATABASE_URL=postgresql://... POSTGRES_TEST_URL=postgresql://... \
node --test --test-concurrency=1
```

Перед ним нужны применённые миграции, собранный Pages editor и установленный браузер Playwright. `CHATX_BROWSER_EXECUTABLE` доступен для почтовых browser-тестов при использовании собственного Chrome. Тестовая БД должна быть отдельной от рабочих данных.

OpenAPI, отдаваемый самим приложением, включает основные операции модуля; их описание находится в `src/email/email-openapi.js`. Снимки настоящего браузера создаются в `artifacts/email/`. Проверенные локальные сценарии не являются подтверждением подключения почтового аккаунта конкретного пользователя или успешного публичного развёртывания.
