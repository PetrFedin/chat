# ChatX: детальный разбор

Основа: чтение репозитория, 2026-10-15. Тесты и сервер не запускались. Незакоммиченные ~443 файла не анализировались.

## 1. Архитектура и зрелость

### Устройство

- Модульный монолит на Node.js ≥20, ESM, PostgreSQL (в CI 17), 6 зависимостей: `@aws-sdk/client-s3`, `livekit-client`, `livekit-server-sdk`, `pg`, `web-push`, `ws` (`package.json`). Свои реализации SMTP, метрик, TOTP.
- `src/`: 129 js-файлов в каталогах по доменам (`messaging`, `task`, `calendar`, `meeting`, `requests`, `wiki`, `vault`, `org`, `integrations` и др.); HTTP-слой `src/http/*` (~5 500 строк, 40 с лишним файлов); `src/server.js` собирает всё.
- Хранение: `db/migrations` (72 файла, 001…072), `db/test_*.sql`; режим памяти для разработки, в production без БД сервер не стартует (`README.md`).
- Клиент: PWA без сборки: `public/app.js` ~6 940 строк, `preferences.js` ~2 150, остальные до 350; 5 css (~118 КБ, минифицированные строки).
- Тесты: `node --test`, 169 файлов в `test/`, у многих тестов вариант с PostgreSQL (`postgres-*.test.js`), браузерный smoke на Playwright (`browser-smoke.test.js`), контрактные (`api-contract`, `openapi-sync`), безопасность (`security-rbac`, `isolation-sweep`, `guest-*`), дизайн-система (`design-system.test.js`, проверяет шкалы радиусов, шрифтов, фокус).
- CI (`.github/workflows/ci.yml`): задание без БД и с PostgreSQL 17; тест `ci-runs-everything.test.js` не даёт перечислять файлы поимённо.

### Безопасность (по найденному коду)

Хорошо: scrypt с индивидуальной солью; в БД хеш токена сессии; HttpOnly + SameSite=Lax; CSP `default-src 'self'`, nosniff, X-Frame-Options (`src/http/helpers.js`); RBAC на сервере, 404 вместо 403 для гостя; лимиты запросов по классам и отдельно на вход (по адресу и по идентичности); одинаковый ответ на сброс пароля; 2FA нельзя снять; сейф с ключом из окружения и журналом раскрытия; HMAC вебхуков; метрики без ПДн; таймауты PostgreSQL; PUSH только на публичный https.

Риски: (1) ключ сейфа в окружении процесса (сказано в `ARCHITECTURE.md`); (2) лимиты хранятся в памяти процесса для общих маршрутов — при нескольких экземплярах считаются отдельно (почтовые попытки в базе — отдельно, это отмечено в `ARCHITECTURE.md`; для общих лимитов подтвердить); (3) сообщения и файлы не шифруются на уровне приложения (подтверждения обратного нет); (4) внешний аудит безопасности не проводился (сведений нет); (5) ИИ-провайдер зарубежный по умолчанию; (6) публичный репозиторий при закрытой лицензии.

### Техдолг

- `public/app.js` ~6 940 строк в одном файле, стили и разметка шаблонами в строках (inline-стили есть, например экран отсутствия связи). Любая правка рискует регрессией; страхуют регулярные тесты по тексту исходника и один браузерный smoke.
- CSS: светлая тема лежит в `preferences.css` (83 селектора `html[data-theme="light"]`), а не рядом с токенами в `styles.css`; ~111 hex-литералов в `styles.css`, 124 в `preferences.css`, 43 в `calls.css` (подробно в `03`).
- Документация расходится: корневой `ARCHITECTURE.md` описывает напоминания, сейф, пометки, почту; принципы — в `docs/ARCHITECTURE.md`; число тестов и миграций в `docs/ROADMAP.md` устарело (59 миграций, сейчас 72).
- **Источник анализа и расхождение с `main`:** анализ выполнен 2026-10-15 по локальной рабочей копии, в которой есть незакоммиченная работа (72 миграции и 169 файлов тестов против 70 и 167 в опубликованном `main`; в локальном индексе часть файлов помечена удалёнными). Файлы, которых в локальной копии не хватало (`src/security.js`, `public/sw.js`, `public/demo.js`, `public/preferences-context.js`, `public/apple-touch-icon.png`, `public/icon.svg`), в `main` присутствуют, поэтому утверждения о нерабочем сервере относятся только к локальной копии. Какая версия считается эталоном, решает владелец; пакет репозиторий не менял.
- Тесты зависят от окружения: без `POSTGRES_TEST_URL` треть набора молча пропускается.

## 4. Что нельзя ломать (инварианты)

**Из `ARCHITECTURE.md` и `docs/ARCHITECTURE.md`**

- Один ответственный на обязательство; завершение исполнителем не равно приёмке.
- Пять разных дат (обещано, прогноз, календарный блок, выполнено, принято) не сворачиваются в одну.
- Изменения владельца, результата, срока, критериев, отмены и переноса не перезаписываются молча: событие аудита с автором и причиной.
- ИИ не принимает ответственность, не меняет срок, не принимает результат, не удаляет историю, не отправляет значимых внешних сообщений. Ответ ассистента только заполняет поле ввода.
- Напоминание — не задача (без ответственного и проверки).
- Личные пометки (избранное, выделения, заметки) всегда ограничены `user_id`, не только `workspace_id`.
- Сейф: нет ключа — 503, никогда не открытый текст; раскрытие записывается в аудит; список секретов не содержит.
- Почта — единственный внешний канал; уникальный индекс «вид письма + событие» против дублей; ответ сброса пароля одинаковый всегда.
- Журнал (`audit_events`) и сама работа не чистятся уборщиком.
- Гость получает 404 вне своей комнаты; чужой — 404, а не 403.
- Идемпотентность на каждой изменяющей команде; `expectedVersion` на задачах, беседах, вики.
- Оргструктура: закрытые подразделения; места считаются в базе.
- Зависимости не добавлять без причины (шесть — осознанное решение).

**Контракты**

- OpenAPI синхронен с маршрутами в обе стороны (`test/openapi-sync.test.js`).
- Миграции накатываются отдельным контейнером; применённые файлы не править (отпечаток, `scripts/migrate.mjs`). CI требует PostgreSQL 17 (миграция 047).
- Отказы инфраструктуры — 503 `STORAGE_UNAVAILABLE`, без внутренних путей.
- Метрики без людей и пространств.
- Оформление: шкала радиусов `--r-1…4`, шкала кеглей 11/13/15/16/17/21/27 и начертаний 400/600/700/800, видимый фокус в обеих темах, отмена движения при `prefers-reduced-motion` (`test/design-system.test.js`).
- Доступность оболочки: `aria-current`, возврат фокуса, ссылка пропуска (`test/accessibility-shell.test.js`).

**Тестовое окружение (из README и заметок владельца)**

- Тесты берут `POSTGRES_TEST_URL`, при отсутствии `DATABASE_URL`; прогон по рабочей базе недопустим.
- После прогона смотреть `# skipped`: должно быть 0, иначе набор не работал.
- База должна быть накачена до последней миграции (`npm run migrate:status`).
- Дев-сервер на той же базе разбирает очереди вебхуков и почты и ворует строки у тестов. Решение: отдельные базы для дев-сервера и набора (например отдельная `chat_suite` на общем контейнере PostgreSQL) или остановка дев-сервера. CI получает собственный сервис PostgreSQL.
- `VAULT_KEY` обязателен для тестов сейфа; без него они проверяют только 503.
- Тесты, создающие сервер, обязаны явно передавать `databaseUrl`, иначе сервер на памяти отвечает 503.
- Старые базы без `schema_migrations` дают сотни ложных падений.

| Изменение | Чем грозит |

| Добавление внешних библиотек (редакторы, сборщики) | потеря принципа минимума зависимостей, рост поверхности атаки |

## Что осталось неподтверждённым

- Реальная работоспособность на боевых данных, нагрузка, поведение при нескольких экземплярах.
- Причина состояния рабочей копии и содержимое различий с HEAD (diff целиком не изучался). `vendor/livekit-client.js` отдаётся маршрутом `src/server.js` из пакета `livekit-client`.
- Полнота шифрования, наличие внешнего аудита безопасности.
- Фактический результат тестов (не запускались).
- Будущая оценка усилий: оценки грубые.
